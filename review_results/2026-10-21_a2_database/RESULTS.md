# A2 (the database layer) 2026-10-21: what was built and what the tests show (owner: "All these done. Now proceed to the next step")

Recourse branch `register-hooks-and-overlay`, NOT on `main`; nothing deployed; the ask route does not use the database yet. Design: `WEBSITE_DESIGN.md` section 4.

## Built
- `api/db/models.py`: 15 tables (users, identities, sessions, consents, chats, messages, notes, feedback, plans, entitlements, usage_events, audit_log, deletion_requests, anon_questions, anon_counters). Rules: everything a person owns is deleted WITH the person (one delete of the users row); usage_events, audit_log and deletion_requests keep no message text and are DE-IDENTIFIED (user_id set to NULL) so billing and audit survive; fixed lists are text columns with CHECK constraints (a new value is a one-line migration); emails stored lower-case (checked); a plan that users hold cannot be deleted. NOT built (Phase C): subscriptions, payments, webhook events.
- `api/db/migrations/versions/0001_initial_schema.py` (Alembic; autogenerated against an empty Postgres, then compared by test with the models), `api/db/session.py` (fails closed without `DATABASE_URL`; rewrites Railway's `postgresql://` for the psycopg 3 driver; imports the database library lazily), `api/db/seed.py` + `api/db/plans.json` (plans and limits as DATA; a changed number is a new version, the old one stays; **the numbers are PROVISIONAL**: anonymous 3 layman a day and no lawyer mode (D4), free 10 layman and 3 lawyer a day, 100 notes; the owner's D7 says real numbers are set at step A5), `api/db/migrate.py` (`python -m api.db.migrate`: upgrade + seed under a Postgres advisory lock).
- Startup migration: with `API_RUN_MIGRATIONS=on` and a `DATABASE_URL` the API brings the schema up to date before its first request and REFUSES TO START if that fails (never printing the address); without the flag nothing is created.
- `/api/health` now reports `"db"`: `not_configured`, `ok` or `down` (a down database does not fail the health check; the reply never carries the address; cached 5 seconds).
- `requirements.txt`: SQLAlchemy 2.0.55, alembic 1.20.0, Mako 1.4.3, psycopg 3.3.6, psycopg-binary 3.3.6, greenlet 3.5.6 (this also changes the WEBSITE's build the day the owner merges; harmless extra packages).

## Tests (`test_api_db.py`, 64 checks, runs against a REAL throwaway PostgreSQL 16 that the test starts and removes; prints SKIPPED and exits 0 where no server exists)
The migration builds exactly the 15 tables and the models do not differ from it; down to nothing and up again works; the seed is safe to run twice and a changed number becomes version 2, then 3; five kinds of bad plans.json are refused; 14 constraints refuse bad data (upper-case email, unknown role/status/document/period/kind/audience, duplicate email, duplicate identity, negative limit); an assistant message keeps the engine's whole result as queryable JSONB; "delete my data" removes identities, sessions, consents, chats, messages, notes and feedback, while the usage row stays with no person and no message, and the audit row and deletion request stay with no person; four services migrating at once make one set of plans and exactly one of them seeds; the migrate command and the startup migration behave as described, including refusing to start on an unreachable database without printing its address; `/api/health` behaves in all three database states.

## Findings on the way
1. **The first throwaway database failed with `TypeError: cannot use a string pattern on a bytes-like object`.** Cause: my sandbox cluster was created with the SQL_ASCII encoding, in which psycopg 3 hands back bytes. It is not a library fault. The test now creates its cluster as UTF-8. Railway's Postgres should be UTF-8 [Likely, not seen]; the owner's step shows the tables so a problem would appear at once.
2. **SQLAlchemy 2.0.55 is pinned, not the newer 2.1.5.** I first installed 2.1.5, blamed it wrongly for finding 1, switched to 2.0.55 and never re-tested 2.1. 2.0 is the conservative choice; 2.1 was NOT tried again.
3. **Without the advisory lock the four-at-once test hung until it was killed** (it did not finish within 280 s), so the lock does matter; that was one run of a deliberately broken copy, not a measurement.
