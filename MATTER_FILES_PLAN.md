- **Today (FOLLOW_UPS 2dl):** a matter = case file + conversations filed under it + notes read with each question. No uploads, no retrieval over documents, no per-matter instructions. The matter's sections are text the model reads, NOT fetched into the prompt.
- **Three sources kept apart:** (1) Instructions: a new `instructions` field in a slot BELOW the Hard rules; the test that the Hard rules are identical stays; instructions must not switch verification off. (2) Context: the case file plus uploaded documents. (3) The law: as now. Every sentence labelled by source ("From your file (p. 4)" / "Law").
- **Beyond a Projects clone:** files PROPOSE facts into the case file (sections charged, arrest date, names; each with its page; the lawyer accepts or edits, so the facts stay the person's); code-checked verbatim quotes from the file with page numbers (the one place a measured error rate looks achievable); fetch the sections charged into the prompt (closes the 2dl gap; feeds the BNSS Schedule I classification and the other-charges button); a "not in your file" statement and a list of missing documents; dates from the file as the input to the default-bail clock (the top bet of the retention plan, unapproved); optional pseudonymisation of names in uploaded text before it goes to a model provider (not legal anonymisation; never touch case names in the law; to be tested); For Individuals upload later.

## Relationship to drafting (recorded 2026-11-19, owner: "Record this in both plan files")
Drafts live INSIDE a matter; the matter is the container, a draft is a work product made from it. A matter would hold instructions, facts (the case file), files, conversations, clocks (not approved) and drafts. A draft is a different kind of object from a Q&A answer: its purpose is a document to file or send; code fills the lawyer's own template (`DRAFTING_PLAN.md`); facts come only from the matter; the law is inserted word for word from the Act shelf; it is versioned and edited, with a cover sheet of checks that is not part of the filing; a wrong statement in it can be filed. **Dependencies, in order:** matter facts (exist; the case file holds only the person's own typed sentences); then uploads (files PROPOSE facts such as FIR number, dates and sections charged, so the lawyer does not retype them; staging only until the legal text exists); then drafting last (its deterministic core uses no model). **The draft check stands alone:** it works on any uploaded Word file with no matter attached (stale law, unverified citations, blanks, mismatched names; no model, no cost), so a matter is not a precondition for it. **Drafting must never become "the model writes from the uploaded files": the rule of `DRAFTING_PLAN.md` stays (the model never writes the law and never invents a fact); a matter full of uploaded documents makes that harder to hold.** Drafting is the riskiest step and is NOT approved; building P0 and P1 of this plan does not start drafting, which needs the owner's go on D0 onwards.
