## Claude's advice, as given
- **Wrong centre of gravity as worded:** responses come from the LAW applied to the person's files, not from the files alone. Files as the main source = "chat with your PDF", which generic tools already do free; the edge is the verified law side (library, Act shelf, wider search, register, checkers).
- **Today (FOLLOW_UPS 2dl):** a matter = case file + conversations filed under it + notes read with each question. No uploads, no retrieval over documents, no per-matter instructions. The matter's sections are text the model reads, NOT fetched into the prompt.
- **Three sources kept apart:** (1) Instructions: a new `instructions` field in a slot BELOW the Hard rules; the test that the Hard rules are identical stays; instructions must not switch verification off. (2) Context: the case file plus uploaded documents. (3) The law: as now. Every sentence labelled by source ("From your file (p. 4)" / "Law").
- **Beyond a Projects clone:** files PROPOSE facts into the case file (sections charged, arrest date, names; each with its page; the lawyer accepts or edits, so the facts stay the person's); code-checked verbatim quotes from the file with page numbers (the one place a measured error rate looks achievable); fetch the sections charged into the prompt (closes the 2dl gap; feeds the BNSS Schedule I classification and the other-charges button); a "not in your file" statement and a list of missing documents; dates from the file as the input to the default-bail clock (the top bet of the retention plan, unapproved); optional pseudonymisation of names in uploaded text before it goes to a model provider (not legal anonymisation; never touch case names in the law; to be tested); For Individuals upload later.
- **What will hurt:** (1) confidentiality and privilege: privacy policy and DPDP consent are placeholders (gate G1), so uploads stay on staging until a lawyer writes them; the "no client names" form rule cannot police files; (2) OCR is the real bottleneck (scans, Hindi or regional language, handwriting; a misread date or section is silent corruption): start with text-extractable PDF and Word only, OCR later with the page image beside the text; (3) cost: a 100-page file is about 55-60k tokens, about Rs 10 extra per answer if stuffed in, about Rs 1 with per-matter retrieval of about 8 passages (arithmetic at $2 per million input tokens; today's per-answer cost is itself an estimate); a per-matter index is small, no vector database needed; (4) uploaded text can contain instructions: files go in as delimited data, with a test; (5) cross-matter leakage: retrieval scoped by user and matter, with a failing-if-broken test; deleting a matter or person deletes files and index (DPDP erasure); (6) no error rate exists: build the file-side harness first (extracted dates, sections and names against a hand-marked set; every file quote exists on the cited page); real FIRs and chargesheets are not public, so start from court orders and synthetic documents (weak evidence until a lawyer marks some).
- **Suggested order if approved:** P0 `instructions` field on matters; P1 upload of text-based PDF and Word, page-numbered passages, per-matter retrieval, answers citing file and page, staging only; P2 facts proposed from files into the case file; P3 fetch the charged sections, then clocks; P4 OCR.
